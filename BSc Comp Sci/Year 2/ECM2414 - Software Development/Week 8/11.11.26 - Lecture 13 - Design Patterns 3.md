
In this lecture, we will go through the decorator pattern, a structural pattern, and then the command pattern, a behavioural pattern.


#### The Decorator Pattern
A **decorator class** *wraps around* a *base class* or *other decorator* to provide more functionality without modifying the base class.

The decorator pattern leverages two OO design principles:
 - *Open-Closed Principle* - Classes should be open for extension, but closed for modification.
	 - Aim to design classes that are easy to extend to incorporate new functionality, but without modifying the original class's code.
 - *Favour object composition* over class inheritance.
	 - Class composition is about wrapping other classes around a class to add functionality rather than subtyping a new class from the original one to add this new functionality.

In order to dynamically add decorators to objects and pass them around in place of the original object, a decorator must have the same supertype as the objects it decorates.

However, as with everything, there are some limitations. Firstly, it takes time and effort to set the decorator structure up, and secondly, it adds new levels of abstraction to the object composition.

#### The Command Pattern
This pattern encapsulates a request for an object to do something as an object.
![[Pasted image 20261111110641.png|421]]

The `Receiver` is the object that you want to do something, e.g. the lights in a room, a garage door, etc, and actually performs the request.

The `Command` interface is a general outline of what a command involves and allows an invoker to dynamically call different commands.

A `ConcreteCommand` is a specific command, such as `LightsOffCommand` for a `Light` object, or `OpenDoorCommand` for a `Garage` object, and is bound to a specific receiver by the client.

The `Invoker` holds a command or set of commands and is what explicitly asks a command to carry out a request and passes in an object to perform the operation on, such as a remote control for the lights in a room or the garage door.

Finally, the `Client` is you, the user (object) who triggers the `Invoker`, e.g., by pressing a button on the remote control, which calls a command on a receiver, such as pressing the button to turn the lights off or open the garage door.
