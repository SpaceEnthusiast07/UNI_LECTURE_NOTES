
In this lecture, we go through the Builder and Singleton Patterns.


#### Builder Pattern
As with all design patterns, the main objective is to decouple certain logic to aid maintainability. Regarding the **Builder Pattern**, its aim is to *decouple* the *construction logic* of a complex object *from the actual representation logic*. This allows you to reuse the same object construction process with different representations/variations of the object.

Below is the UML diagram showing how the Builder Pattern is implemented.
![[Pasted image 20261106095912.png|288]]

**Product**
This is the object that is going to be constructed.

**Builder**
This interface defines WHAT steps are involved in the construction process of the product.

**ConcreteBuilder**
This concrete class defines WHAT is involved in EACH step.

**Director**
Hence the name, the Director is responsible for performing the steps outlined in Builder interface in the correct order.


#### Pizza Builder Example
**Product**
This will be the `Pizza` class:
```Java
class Pizza {
	priavte String dough = "";
	priavte String sauce = "";
	priavte String topping = "";
	
	public void setDough(String dough) {
		this.dough = dough;
	}
	
	public void setSauce(String sauce) {
		this.sauce = sauce;
	}
	
	public void setTopping(String topping) {
		this.topping = topping;
	}
}
```

**Builder**
This defines the steps involved in the construction process:
```Java
abstract class PizzaBuilder {
	// 
	protected Pizza pizza;
}
```
