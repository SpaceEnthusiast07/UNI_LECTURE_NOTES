
#### Nested Classes
The reason we have nested classes arises due to the problems with encapsulation.

With two tightly coupled classes, one would like to access the other's private members, but, by the definition of `private`, this is not possible. Therefore, we implement *getters* and *setters* for these private members to allow access. However, now any class has access to the private members, rendering the essence of "private" useless. We want a way to allow only specific classes access to these members.

This is where nested classes come in. You simply define another class *within* the base/outer class. This means the outer class's members can be private, but can also be freely accessed from within the nested class, without any problems.

With the use of nested classes comes some restrictions: the outer class can only be defined with the `public` or implicit `package-private` access modifiers, whereas the nested class can have any.

As you can see from the code snippet below, to access the `Engine` class you must use the dot operator in conjunction with the `Car` class: `Car.Engine`.

Below is an example using a Car and Engine class.
```Java
class Main {
	public static void main (String[] args) {
		Car car = new Car();
		System.out.printf("Getter: %d\n", car.getSpeed());
		
		Car.Engine engine = car.new Engine();
		engine.showCarSpeed();
	}
}

// Outer class
class Car {
	private int speed;
	public void accelerate() {
		this.speed += 10;
	}
	
	public int getSpeed() {
		return speed;
	}
	
	// Inner class
	class Engine {
		public void showCarSpeed() {
			System.out.println(speed);
		}
	}
}
```

There are two types of nested class: *Static Nested Class* and *Inner Class*.

A **Static Nested Class** is a nested class that is static - it doesn't have access to instance members, only static ones.

An **Inner Class** is a regular nested class - has access to instance members.


#### Inner Classes
Due to the nature of being nested, they can be hard to spot in code.

At compile time, two class files (byte code files) will be produce: `OuterClass.class` and `OuterClass$InnerClass.class`.

From within the outer class, an inner class can be instantiated directly: `Engine AudiEngine = new Engine();`, but from outside the outer class, the inner class can only be instantiated using the outer class name: `Car.Engine AudiEngine = Audi.new Engine();`.

The functionality of `this` is logical, but needs thought. When inside the inner class, `this` refers to the current instance of the inner class. Similarly, when directly inside the outer class, `this` refers to the current instance of the outer class. But to access the current outer class's instance from within the inner class, you must proceed the `this` keyword by the outer class name and the dot operator: `OuterClass.this.InstanceMember`.


#### Local Classes
Remember that when we typically use the word "local", we are usually referring to local variables within functions. This can give you a pretty good idea that **local classes** are classes that are *defined within methods* and *exist solely within them*.

Since they exist solely inside methods, *they cannot be accessed outside of the method*, similar to local variables. Local classes are also `package-private` ONLY and *cannot access the enclosing method's local variables*, unless passed in as arguments or are `final`. But, they *can access all members from the outer class's instance*.


#### Anonymous Classes
As the name suggests, these are *classes that are defined without a name*. Anonymous classes can be defined within methods and even method arguments.

When defining an anonymous class in a method, you simply define the class body when you instantiate the anonymous class. Below is an example:
```Java
class OuterClass {
	public void OuterClassMethod() {
		Object AnonymousClass = new Object() {
			public void printHelloMessage() {
				System.out.println("Hello world from inside an anonymous class.");
			}
		}
		
		AnonymousClass.printHelloMessage(); // Comiler Error - cannot find symbol
	}
}
```

As you may have noticed that the reference and instance type of this class is the `Object` class. This is for good reason; for an anonymous class to work, it must either implement an interface or extend a class. So I used the `Object` class for simplicity.

Because an anonymous class must extend another class or implement an interface, its reference type is of the extended class or interface, meaning that if you create a new method inside the anonymous class, the compiler cannot find that method definition, as it is not already defined some what in the reference type class. Therefore, new methods inside anonymous classes can only be accessed from inside the anonymous class itself.

Therefore, if you want to call an anonymous class's function, it must be inherited or overridden.
