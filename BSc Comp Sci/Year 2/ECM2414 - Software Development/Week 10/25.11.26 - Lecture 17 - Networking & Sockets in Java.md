
#### Networking Recap
Communication between two machines follows a strict hierarchical approach, known as the TCP/IP protocol stack, which breaks the steps down used for communication into layers:
 - Application - HTTP, FTP, Telnet, etc
 - Transport - TCP, UDP
 - Network - IP
 - Link - Device drivers, MAC, etc


#### Networking in Java
Since our Java programs are applications, we will be operating in the *application layer* of the TCP/IP stack.

The `java.net` API is used for networking in Java applications.

When setting up networking in Java, we need to specify which transport layer protocol to use, TCP or UDP.


#### Transmission Control Protocol (TCP)
**TCP** is a *connection based* protocol meaning before the transmission of data, a link between the sender and recipient is established to ensure the recipient is on and ready to receive data, which *guarantees delivery* of data due to the recipient sending *acknowledgments*.

TCP is an *end-to-end communication* protocol, meaning it utilises the IP address and port number of the sending and receiving applications, rather than the link layer which governs routing between intermediate devices (hops between routers).

One key property of TCP is that the *order of data received is guaranteed* because its uses sequence numbers on packets of data, which are reassembled on arrival.

Another key property is that TCP will re-transmit data in the event data is lost or an acknowledgment from the recipient hasn't arrived within a certain amount of time.
