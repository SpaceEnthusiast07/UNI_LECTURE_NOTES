
#### Collections
A **collection** is an object that *groups multiple elements* (objects) into a single unit.

You might be wondering why we would use a collection to store multiple objects rather than an object array; well, arrays for static, but a collection is dynamic, providing more flexible storage options; e.g., linked list object.

Since collections store objects, you would want to specify which object to store; hence, collections heavily use generics.

You might be able to guess the difference between a `Collection` and a `Map`. A `Collection` stores multiple, single objects, hence a single generic type parameter: `Collection<E>`. However, a `Map` stores key-value pairs, so the type parameters are: `Map<K, V>`.


#### Set
The **set** interface, as we know from maths, is a collection of *unique objects* that have *no particular order*

There are three concrete implementations of sets:
 - `HashSet<E>` - fastest, but doesn't preserve order of insertion, and usually has a `HashMap<K,V>` behind the scenes
 - `TreeSet<E>` - uses a red-black (rows alternate between red and black) self-balancing binary search tree structure, and slower than `HashSet<E>`.
 - `LinkedHashSet<E>` - order of insertion is preserved, and stored in a hash table with a linked list running through it.


#### List
The **list** interface, which is the collection you would most likely use, is a *dynamic* collection of objects that *allows duplicates* and *preserves the order* of insertion.

There are two concrete implementations of list, one you will have used and the other have created your self:
 - `ArrayList<E>` - uses regular arrays under the hood with a default size, but once it is filled to a certain point, new array is created and previous array contents are copied over.
 - `LinkedList<E>` - uses a doubly linked list, faster for insertions, but slower for index lookups.


#### Queue
The **queue** interface is a collection of objects with the intent to process in a first-in-first-out manor.

This collection contains all the methods you expect to perform on a list.


#### Deque
You might think this means "de-queue", which would be weird, as that is an operation, not a collection in itself.

Well, you'd be right. Deque stands for "double-ended queue"; i.e., you can add and remove from the head and tail of the queue.
