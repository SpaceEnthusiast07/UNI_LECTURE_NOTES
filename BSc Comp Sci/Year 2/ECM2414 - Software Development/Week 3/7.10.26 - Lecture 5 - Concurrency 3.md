
#### Recap
**Race conditions**
When two threads try to access the same data at the same time, but don't know which should have access.

**Livelock**
When two threads spend too much time avoiding each other and not getting any useful work done.

**Deadlock**
When two threads need access to a recourse, but the other thread is holding it. It is a stalemate and no useful work gets done.


#### Visibility
**Fresh Data**
When threads are accessing data, we need to ensure it is **fresh**; the *data is up-to-date*.

**Stale Data**
When the *data is not up-to-date*, it is known as **stale data** - intuitive 😂.

An example of visibility in action is with the `++` increment operator. Below is some example code:
```Java
class Counter {
	private int c = 0;
	void increment() { c++; }
	int value() { return c; }
}

public class Main {
	public static void main(String[] args) throws Exception { 
		Counter counter = new Counter();
		
		// Uses a lambda expression; explained later on
		Thread t1 = new Thread(() -> { 
			for (int i = 0; i < 100000; i++) counter.increment(); 
		});
		
		Thread t2 = new Thread(() -> {
			for (int i = 0; i < 100000; i++) counter.increment();
		});
		
		t1.start(); t2.start();
		t1.join(); t2.join(); 
		System.out.println("Expected: 200000");
		System.out.println("Actual: " + counter.value());
	}
}

-- OUPUT 1 -----------------------------------------------------------------------
Expected: 200000
Actual: 180689

-- OUPUT 2 -----------------------------------------------------------------------
Expected: 200000
Actual: 124996
```

Firstly, lets understand the `join()` method, as we already understand `start()`.

When a thread, e.g. `ThreadA`, calls the `join()` method on, for example, `ThreadB`, specifically `ThreadB.join()`, `ThreadA` pauses its own execution and waits for `ThreadB` to complete. Once `ThreadB` has finished, `ThreadA` resumes its execution.

Applying this understanding to the program above; the main program, `Thread-Main`, calls the `join()` method on both `Thread1 (t1)` and `Thread2 (t2)`, meaning `Thread-Main` will wait until both `Thread1` and `Thread2` have finished before it resumes its execution.

Now, onto the main point of this example code: the differing outputs. This arises because whilst `Thread1` has read `c` and is now performing the increment operation, `Thread2` is also reading `c`. This causes `Thread2` to read *stale data* (out-of-date data). So, once `Thread1` has finished and writes its update to `c`, it is immediately lost when `Thread2` writes its own updated `c`. To avoid this, we use volatile or atomic variables, explained below.


#### Atomic Actions
These are operations that must not be interrupted mid-operation.

For example, the increment operator `++` consists of 3 steps: read, manipulate, and write.

This is where **atomic variables** come in. These are imported objects that ensure operations performed on them are uninterruptable. 

To access these atomic variables, you must import `java.util.concurrent.atomic`, which gives you access to atomic primitive types, such as `AtomicInteger`, `AtomicLong`, `AtomicBoolean`, etc.

These are objects so have functions used to manipulate the data, such as `get()`, `set()`, `increment()`, `decrement()`, etc.

#### Volatile
By marking a variable as **volatile**, it signals to the JVM to *stop local thread caching* of the variable value and makes sure that *each thread reads the new value once it has been updated*.


#### Publishing and Escaping
**Publishing** refers to *making an object available outside its original scope*. This is done by providing a reference to this object to another program.

You *must not publish* an object *unless you really have to*. If an object is *published by accident*, that *object is said to have escaped*.


#### Thread Confinement
Thread confinement refers to the idea that if data doesn't need to be shared between threads, then that data can be confined to the single thread that needs access.

By confining data to a single thread, this automatically ensures thread safety.


#### Lambda Expressions
Lambda expressions *introduce aspects of functional programming* into Java.

A **lambda expression** is a *block of code with optional arguments* that you can *pass between objects*; previously, you could only pass objects and primitives between objects.

The format of a lambda expression is: `(arguments) -> {body of code}`.

There are some extra notes that make sense:
 - You can have 0 or more arguments - with 0 you must have empty brackets
 - With a single argument, the brackets can be omitted
 - The argument type can be declared or inferred
 - The curly brackets can be omitted on the body with only one statement
