
#### Normalisation
**Normalisation** is a method used to *enhance* the relational model.

It is a process that allows us to *produce a set of relations*, in the relational model, *with desired properties*.

The properties are to remove redundancy, and the potential or insertion, modification, and deletion anomalies.

**Insertion** anomalies occur when a new record or tuple is added to the database, but not all information is available to fill in its attributes, leading to null values.

**Modification** anomalies occur when you have duplicate records/tuples in the database and update an attribute in one duplicate, but not the other.

**Deletion** anomalies occur when you have two distinct entities in the same relation/table and need to delete some data (some attributes), but this also deletes all data in the record/tuple (all attributes).


#### Functional Dependencies
Given two attributes $A$ and $B$ from a relation $R$ where attribute $B$ is functionally dependent on attribute $A$, denoted $A \rightarrow B$, the value of $A$ will *uniquely identify* the value of $B$.

In the notation $A \rightarrow B$, $A$ is known as the *determinant*.

The most obvious example is with the primary key: given the primary key, you can uniquely identify any other attribute.

As you may have already noticed, functional dependencies are not necessarily commutative; i.e., $A \rightarrow B \neq B \rightarrow A$.

$\text{studentID} \rightarrow \text{studentName, DoB, postcode, city}$
$\text{postcode} \rightarrow \text{city}$

A **transitive dependency** is one in which if $A \rightarrow B$ and $B \rightarrow C$, then $C$ is transitively dependent on $A$ through $B$: $A \rightarrow C$.

A **partial dependency** is where a non-key attribute functionally depends on only part of the primary key, if the primary key is a composite key.

$A \rightarrow B$ is a **full dependency** if $B$ is not functionally dependent on any subset of $A$.

#### Process of Normalisation
**1st Normal Form**
Each attribute of a tuple must contain a single, *atomic value* rather than a list of values.

To resolve this, we can create new, duplicate tuples, which have an atomic value in each attribute.
