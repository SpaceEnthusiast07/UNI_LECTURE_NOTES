
#### SQL
SQL stands for **Structured Query Language** and was developed in 1974 by IBM, to support Edgar Codd's (yes, the Codd in BCNF!) relational model.

SQL is a *declarative language*, meaning you state WHAT you want (the result), and the DBMS has algorithms for HOW to perform your SQL requests.

SQL is a *domain-specific language* (DSL), unlike general purpose languages like Python, Java, and C++; it's sole purpose is to interact with relational databases.

In the previous lecture we learnt about relational algebra; well, the DBMS converts your SQL queries into relational algebra so it can perform the requests on the database.

SQL uses *free formatting* - you can freely use line breaks and indentation to improve readability; and its *keywords are case insensitive* - you can type them in lower or upper case, but the convention is to write them in all upper case. However, SQL queries will always end with a semicolon `;`.


#### Sections of SQL
The commands within SQL are grouped based on what they do and what they manipulate.

**Data Definition Language (DDL)**
These commands are used to define the structure (schemas) of the database and control access; and include `CREATE`, `DROP`, `GRANT`, etc.

**Data Manipulation Language (DML)**
These commands are concerned with manipulating the raw data inside tables/relations. They include `SELECT`, `INSERT`, `UPDATE`, and `DELETE`.


#### The SELECT Command
Below is the general format of the `SELECT` command. Square brackets indicate that the statement within is optional.
```SQL
SELECT [DISTINCT] attribute_names
FROM table_names
[WHERE condition]
[GROUP BY attribute_names]
[HAVING condition]
[ORDER BY attribute_names];
```

**SELECT**
Remember projections ($\pi_{<\text{attribute list}>}(\text{relation name})$), which create a new relation containing only the specified attributes from the provided relation; well, that's what `SELECT` does, the resulting relation only contains the desired attributes.
Also, you can use a wildcard such as `*` to mean "all attributes", but it is a rule of thumb to manually specify all the attributes you want.
`DISTINCT` is rather self-explanatory, it means to only include the unique values; i.e., if two tuples/rows match exactly, then they are compressed into one.

**FROM**
Then, the `FROM` command joins ($tableA \; \bowtie \; tableB$) the relevant tables together so only one big table has to be searched.

**WHERE**
This is the keyword used to filter the output based on rows, rather than attributes which `SELECT` does. You specify Boolean conditions relevant to the attributes.
You have many different Boolean operators:
 - *Comparison*: `=`, `<> (!=)`, `<`, `>`,`<=`, `>=`
 - *Range*: `BETWEEN ... AND ...`, `NOT BETWEEN ... AND ...`
	 - Inclusive at both ends of the range
 - *Set membership*: `... IN ...`, `... NOT IN ...`
	 - Lists are specified using curved brackets: `('Hello', 'World!')`
 - *Pattern matching*: `... LIKE <regex>`, `... NOT LIKE <regex>`
	 - You use regular expressions with `LIKE`, such as `'a%'`, which means all strings that start with `a` and have any number of characters after that
	 - `%` means 0,1, or more characters; and `_` represents any single character
 - *Nullability*: `... IS NULL`, `... IS NOT NULL`
	 - `NULL` is a state not a value, so `=` doesn't work
 - *Standard Bool Ops*: `OR`, `NOT`, `AND`

**ORDER BY**
This is used to sort the output of the query based on one or more attributes. You can also specify the order to be in ascending (`ASC`) or descending (`DESC`), but the default is ascending, so `ASC` can be omitted.

**Aggregate Functions**
These are functions used to calculate individual values and are specified within the `SELECT` part. Aggregate functions include `COUNT`, `MIN`, `MAX`, `SUM`, and `AVG`; they all have self-explanatory names so you should be able to understand what they do. Just one side note about `COUNT` though, when you use it with the `*` wildcard, it includes `NULL` values, otherwise it, and all others, don't. Also, you specify the attribute on wish you want to perform the calculation.
