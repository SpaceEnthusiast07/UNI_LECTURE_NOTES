
You may have noticed that we only went through `SELECT` from the Data Manipulation Language (DML) and left out `GROUP BY` and `HAVING`, but this lecture we go through the rest of the DML!


#### Executing an SQL Query
Obviously, the DB engine doesn't execute the SQL commands in the order you specify them, it has its own logical order:
 - `FROM` - Identify the source tables.
 - `WHERE` - Filters individual rows that don't satisfy the Boolean condition.
 - `GROUP BY` - Collapses the remaining rows into groups, and calculates aggregate functions.
 - `HAVING` - Like `WHERE`, but for groups instead of the whole table.
 - `SELECT` - Chooses the output columns/attributes and expressions.
 - `[DISTINCT]` - If used, removes duplicate result rows.
 - `ORDER BY` - Sorts the final resulting rows based on a certain column/attribute.


#### GROUP BY
The `GROUP BY` command groups rows based on a certain attribute/column, then calculates statistics on those groups, via aggregate functions.

Therefore, the `SELECT` command can only include aggregate functions and the attributes that have been used to group the rows.

**Example**
Given a `Customer` table, we want to know know many customers are from each country. We can use the `GROUP BY` command to group customers by which country they live in, then use the `COUNT` function to count the number of customers in each country:
```SQL
SELECT COUNT(CustomerID) AS 'Number of Customers', Country
FROM Customer
GROUP BY Country;
```

The `GROUP BY` command can be used in conjunction with `HAVING`, which is used to filter the groups by a certain Boolean condition, much like `WHERE` filters rows based on a Boolean condition.

**Example**
Using the same context as with the example above, we might only want to know how many customers are from certain countries. We can achieve this using the `HAVING` command:
```SQL
SELECT COUNT(CustomerID) AS 'Number of Customers', Country
FROM Customer
GROUP BY Country
HAVING Country IN ('UK', 'US', 'Canada', 'France');
```


#### AS
`AS`, standing for Alias, is used to give things custom, temporary names to aid the readability of the SQL query and the output.

You can use `AS` to make column/attribute names more user friendly, or use it to shorten the name of tables when you are querying multiple tables in a single query.


#### Subqueries
A subquery is a `SELECT` statement inside another. This allows you to perform more complex queries, ones involving you needing to find some information about the database, then using that to find out more information.

A subquery can appear in a `WHERE`, `HAVING`, `SELECT`, or `FROM` command.

You can use the `IN` command to check whether a value of the outer query is an element of the result of the subquery.


#### JOINS
A `JOIN` combines two or more tables in the horizontal direction; i.e., side-by-side. We know about joining tables from relational algebra.

To `JOIN` two or more tables, we concatenate rows together that have equal values in certain attributes/column, which we specify as the *join condition*. The most common join condition is the primary key in one table with the foreign key in another.

From relational algebra, we have the cartesian product (all rows to all rows) of two tables, and the equijoin (based on join condition) and natural join (equal common attributes).

There are different types of joins based on what you want out of the join: `INNER JOIN`, `LEFT JOIN`, `RIGHT JOIN`, and `FULL OUTER JOIN` (MySQL doesn't fully support this join).

Below is the general format of a `JOIN` in MySQL and where is goes:
```SQL
SELECT attribute_names
FROM table1
[JOIN TYPE] table2 ON table1.attribute_name = table2.attribute_name;
```

The `JOIN TYPE` is optional as the default is `INNER JOIN`.
