In the previous two lectures, SQL 1 and 2, we went through the basics of SQL and the Data Manipulation Language (DML), which includes the `SELECT`, `INSERT`, `UPDATE`, and `DELETE` commands. In this lecture, we refresh ourselves on the last three commands and then start learning about Data Definition Language (DDL) and Data Control Language (DCL).


#### INSERT
`INSERT` allows you to add a new row/tuple to a specified table/relation. Below is an example use of the `INSERT` command:
```SQL
INSERT INTO Orders
(OrderID, CustomerID, OrderDate)
VALUES
(10444, 90,‘2017-05-25’),
(10445, 15,‘2017-05-25’),
(10446, 66,‘2017-05-26’);
```

`INSERT` is used alongside `INTO` to specify the table and order of attributes to add, and `VALUES` to specify the new rows to add.

You can also use the `INSERT` command alongside the `SELECT` command: `SELECT` data from another table and `INSERT` it into this table.


#### UPDATE
`UPDATE` is used to change the values of specific attributes in a table.

```SQL
UPDATE Custoemrs
SET ContactName = 'Alfred Schmidt', City = 'Frankfurt'
WHERE CustomerID = '001';
```

`UPDATE` is used alongside `SET` to specify which attributes to change and what to set them to, and `WHERE` so you only update the rows/records/tuples you want to.

You can perfectly normally use `UPDATE` without a `WHERE` clause, but all rows will have the update applied to them.


#### DELETE
`DELETE` is used to delete certain rows from a table.

```SQL
DELETE FROM Orders
WHERE OrderDate < CURRENT_DATE()-30;
```

Warning: Omitting `WHERE` will delete everything from the table.


#### Data Definition Language (DDL)
The DDL defines a set of SQL commands that directly manipulate schemas; i.e., tables. The commands included are `CREATE`, `ALTER`, and `DROP`.


#### Data Types in MySQL
 - Numeric - `INT(n)`, `TINYINT(n)`, `DECIMAL(p,s)`, `FLOAT`, `DOUBLE`
 - String - `CHAR(n)`, `VARCHAR(n)`, `TEXT`
 - Date/Time - `DATE`, `TIME`, `DATETIME`, `TIMESTAMP`
 - MySQL includes many other types and other DB systems might have different types.


#### CREATE
`CREATE` allows you to create a new table by specifying its name and attributes, along with datatypes and constraints. Below is an example use of `CREATE`.

```SQL
CREATE TABLE IF NOT EXISTS Tasks (
	task_id INT AUTO_INCREMENT PRIMARY KEY,
	title VARCHAR(255) NOT NULL,
	start_date DATE,
	due_date DATE,
	status TINYINT NOT NULL,
	description TEXT,
	created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=INNODB;
```

The default database storage engine in MySQL is INNODB, so you can omit this line.

The general format for an attributes definition is:
```SQL
attri_name data_type[(length)] [NOT NULL] [DEFAULT value] [AUTO_INCREMENT] [column_constraint]
```


#### Constraints
`NOT NULL`
Ensures values stored in an attribute are not `NULL`; i.e., a concrete value must be provided.

`UNIQUE`
Ensures values of an attribute are unique; i.e., no duplicates. There are two ways to specify uniqueness; one is inline like you saw in the example of `CREATE` above, and the other is a separate line with this format: `[CONSTRAINT constraint_name] UNIQUE(attribute_list)`.

`CHECK`
Ensures values in an attribute or group of attributes satisfy a Boolean expression. Like `UNIQUE`, you can use `CHECK` inline or as a separate statement: `[CONSTRAINT constraint_name] CHECK(Boolean_expression)`.

`PRIMARY KEY`
This ones obvious, but marking an attribute as a `PRIMARY KEY` makes it implicitly (DB engine automatically inserts) `NOT NULL` and `UNIQUE`, what a surprise! Now you may wonder about composite primary keys, well you simply add a separate statement for the primary key: `[CONSTRAINT constraint_name] PRIMARY KEY(attribute_list)`, simple!

`FOREIGN KEY`
Used to represent a relationship between tables/relations, and is the primary key of another table. To use foreign keys, you add the custom, or not custom, attribute name to the list of regular attributes when creating a table. Then, at the end of the list, amongst the constraints, you specify a foreign key constraint. The general format is: `[CONSTRAINT constraint_name] FOREIGN KEY (attribute_name or list) REFERENCES parent_table`

Now, there are some conventions for naming constraints, specifically prefix each with:
 - `uc_`: unique constraint
 - `pk_`: primary key constraint
 - `fk_`: foreign key constraint
 - `chk_`: check constraint
