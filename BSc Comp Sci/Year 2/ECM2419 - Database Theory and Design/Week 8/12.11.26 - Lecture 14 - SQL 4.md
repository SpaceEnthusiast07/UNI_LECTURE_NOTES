In the last lecture, we went through the commands in the Data Definition Language (DDL), but in this lecture, we will be learning about more commands in the DDL, specifically about `AUTO INCREMENT`, `INDEX`, and `VIEW`.


#### AUTO INCREMENT
`AUTO_INCREMENT` tells the database engine to generate a new unique number for a particular attribute when a new row/tuple/record is added.

This `AUTO_INCREMENT` feature is mainly used with the primary key. When adding new records to the table, simply omit the `AUTO_INCREMENT` attribute in the list of values and the database engine will automatically insert it.

You can also specify the starting point for `AUTO_INCREMENT`:
```SQL
ALTER TABLE Customer AUTO_INCREMENT = 100;
```


#### INDEX
An index is a balanced tree, a B+ tree, that allows MySQL to find rows faster. The aim is for each level of the index to be as small as possible so a linear search through it doesn't take much time at all.

Naturally, indexes take up more storage space than a non-indexed database, and every time a table is updated, the index has to be updated to reflect these changes; so, only create indexes on columns/attributes that will be queried frequently enough to offset the added time to update the index.

There are two ways to create a custom index: one is to add a new statement in the table creation SQL statement, such as `INDEX idx_persons (lastName)`; or to create one on an existing table, such as `CREATE INDEX idx_persons ON Persons(lastName)`.

Once an index is created on an attribute/column, any query that utilises this indexed attribute will search through the index instead of a regular linear search through the whole table.

By now you may have thought of an attribute that would be queried extremely frequently, the primary key! By default, MySQL creates a special index called PRIMARY for the primary key of the table. There is a SQL query that you can perform to see what indexes are present on a table: `SHOW INDEXES FROM table_name`.

Like anything, you can remove an index from a table simply by stating:
```SQL
ALTER TABLE Staff
	DROP INDEX idx_staff_name;
```


#### VIEW
A **view** is a virtual table that is the result of an SQL query. In simple terms, a view is a *saved, named SQL query*/statement. Below is the basic definition structure of a view in MySQL:
```SQL
CREATE VIEW view_name AS
	custom_sql_query;
```

There are two types of views: a horizontal and vertical view.

**Horizontal Views**
This is the most natural version of a view and you can think of it as performing horizontal slices in the table to include certain rows/records.
```SQL
CREATE VIEW Staff_Department_20_View AS
	SELECT *
	FROM Staff
	WHERE departmentID = 20;
```

**Vertical Views**
These views perform "vertical slices" on the table to return specific columns/attributes.
```SQL
CREATE VIEW Staff_No_Salary AS
	SELECT staffID, sFName, sLName, hireDate, departmentID
	FROM Staff;
```

Obviously, you are not limited to one or the other, you can combine the concept of a horizontal and vertical view into one view definition.

Now, this is an important note, by default, view are two way: you can perform extra SQL queries on a view to read data from their base tables, or update the data in their base tables. However, you can setup a view to be read-only to ensure no data is accidentally modified. Note that views that use a group clause are automatically read-only.

You can use `WITH CHECK OPTION` at the end of a view definition to specify that any update through the view will have to satisfy its `WHERE` clause, which means that if the result of the external SQL query means some rows aren't in the view anymore, it would be rejected.

Like anything, you can drop a view by simply using `DROP VIEW view_name;`.
