
#### File Based System
This is where each application stores and manages its own data.
![[Pasted image 20260924103938.png|384]]
From this diagram, you can see that the data for Sales and Contracts is completely isolated and must have a dedicated system for sharing.
You can also determine that each department will probably store their data in different formats from each other, and may have duplicate data between them, such as the customer details.

Pros:
 - End user has total control of data storage - no intermediatory 
 - No restriction to when data or app is modified
Cons:
 - Data duplication - wasted storage on duplicated data and inconsistencies with which is correct
 - Data dependency - if a new field must be added, such as term-time address in a uni system, the application must also be updated to "understand" this new field.
 - Incompatible file formats - different file systems may use different formats to store their data, resulting in incompatible communication (data sharing).
 - Numerous application programs - to retrieve more data from the file, end users must create more applications to handle these new queries, which becomes hard to manage at scale.


#### Database System
A database system is the collective name for the database itself, the DBMS, and one or more database applications.

With this model, multiple, independent applications can interface with a single universal data store. The below diagram illustrates this idea.
![[Pasted image 20260924104301.png|414]]

From this diagram, you can see that both departments, Sales and Contracts, have access to the same data, but through their own dedicated *Database Application* (an application that interacts with a database at some point during its execution), which interfaces with the DBMS, then the actual database.

To query the database, end users write standardised queries using a specialised language called SQL (Structured Query language). The DBMS then parses this query and performs the requested action.


##### Database Management System (DBMS)
This is the piece of software that sits in between a database application and the database itself.

It parses the SQL query sent from the database application and performs the request on the database.

The DBMS provides a range of different advantages:
Control of data redundancy • Data Consistency • Sharing of Data • Improved data integrity • Improved Security • Enforcement of Standards • Economy of Scale • Balance of conflicting requirements • Improved data accessibility and responsiveness • Increased Productivity • Improved maintenance through data independence • Increased concurrency • Backup and Recovery services
