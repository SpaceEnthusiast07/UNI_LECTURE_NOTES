
#### The 3-Level Architecture
**External Level**
This level contains different views; a **view** being a *certain query output of the database*. It sounds scary, but it is simply the resulting table you see after querying the database; it contains a smaller number of fields and records, specific to your SELECT and WHERE parameters in your SQL query.

**Conceptual Level**
This level contains the *metadata* for the database; *what* data is stored (attributes and tables/entities) and the relationships between the data/entities. This level deals with the logical structure of the data, so should not contain any storage specific metadata.

**Internal Level**
This level describes *how* the data is stored.


#### Objectives of 3-Level Architecture
The 3-Level Architecture aims to achieve data abstraction and independence.

**Data Abstraction**
This is about hiding the specifics of the database organisation and providing the user with a simplified conceptual view of the database. Basically meaning that the user doesn't have to worry about how the database works, they just use (query) it.

**Data Independence**
This is were a level is unaffected by changes to the level directly below.
There are two types: physical independence - you can change how data is stored (internal level) without affecting or changing what data is stored (conceptual level); logical independence - you can add a new entity or attribute (change conceptual level) without changing how the user views the data (external level).
However, you may have guessed that if you change one level, you must change the level below it; such as updating the conceptual level leads to an update in the internal level, makes sense.


#### DB Schema vs. State
The **schema** of a database, the database schema, is the *description of the structure of the database*. Below is the format of the schema and an example:
```SQL
Table_Name(primary_key, field_2, field_3, ..., foriegn_key)

-- Example -----------------------------------------------------------
Department(dept_id, dept_name)
Employee(emp_id, emp_name, address,dept_id)
```

A **database state** is the *content of the database at a particular point in time*.
