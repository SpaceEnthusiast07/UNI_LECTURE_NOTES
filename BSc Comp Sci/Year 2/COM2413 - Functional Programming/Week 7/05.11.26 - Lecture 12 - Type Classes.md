
#### Type Classes
Despite their name, they are NOT classes and the functional programming guys should have left the name "class" alone!

Anyway, generally, it is usually convenient to use the same name for different, but related, applications. This process is known as **overloading** and is a form of polymorphism, where the *same function name or operator can represent different implementations*, and the compiler selects which version to use based on the types, and sometimes number, of arguments. One way we can implement overloading in Haskell is to use type classes.

A **type class** defines a *set of functions* that *different data types can share*. Counter to my statement at the start, the reason they are called type classes is because they define what a data type can do, similar to what an object oriented class defines what an object can do and the data it holds.

To help explain an example of a type class, I am going to use the idea of object serialisation from the OOP module in term 2 year 1. However, the process of serialisation isn't restricted to objects; you can serialise anything into a bit stream to send over a network or store in secondary storage. As we all know, the industry standard package for sending data over the internet is JSON (JavaScript Object Notation).

```Haskell
-- Type class to serialise ANY datatype
-- We use String here to represent our JSON
class Serialisable a where
	serialise   :: a -> String
	deserialise :: String -> a

-- We can instantiate the type class for as many types as we want
instance Serialisable Int where
	serialise a = show a
	deserialise b = read b

main :: IO ()
main = print (serialise (14 :: Int))

-- OUTPUT ------------------------------------------------------------
"14"
```

Notice the use of `14 :: Int`. This isn't redundant, but crucial. To the Haskell compiler, there is no way of knowing whether `14` is an `Int` or an infinite precision `Integer`, and since we have only defined our serialiser for the type `Int`, we must explicitly tell the Haskell compiler that our `14` is an `Int`, not an `Integer`.

Now, you may be wondering or you may not be, either way, I am going to tell you why type classes accepting lists is different. Its quite simple. Continuing with our serialisation example, the only way to serialise a list of elements is if you can serialise an element; hence, you must add a special condition to the start of our new `Serialisable` instance indicating that individual elements must be `Serialisable`.

```Haskell
-- ...
instance (Serialisable a) => Serialisable [a] where
	serialise as = show (map serialise as)
	deserialise bs = map deserialise (read bs)
-- ...
```
