#### Functions
Functional programming is solely based around functions, functions being the sole operation!

A **function** transforms its inputs to produce a single output.

**Inputs** (plural) are known as *arguments* and the **output** (singular) is known as the *result*.

In functional programming, a function is known as *pure*, meaning it only performs operations on its inputs (its arguments); a function cannot reach out to a global variable.

>[!Warning] There is no such thing as iteration, only recursion!!!

For any two functions, `f` and `g`, the composition is written as `(f . g) x = f (g x)`.

**Function guards** are the *base condition* from the world of mathematics and recursion! They allow a recursive function to terminate and not execute forever.

Function Format:
```Haskell
function_name arg_1 arg_2
 | boolean_guard_1 = output_1
 | boolean_guard_2 = output_2
 | otherwise (or simply True) = output_3
```

Using a function:
```Haskell
function_name arg_1 arg_2
-- OR ----------------------------------------------------------------
function_name(arg_1 arg_2)

-- Brackets can be used
-- Also, "--" are used to denote a comment!
```


#### Example: Writing Fibonacci
```haskell
fib n
 | n == 0    = 1
 | n == 1    = 1
 | otherwise = fib (n-1) + fib (n-2)
```

Perfect answer!!


#### Strong/Static Typing
Haskell is a strongly/statically typed language, meaning you must define the types of everything, variables have the same type forever and the Haskell compiler will never type convert for you.


#### Type Definitions
Without function type definitions, the Haskell compiler will *infer* the type (s) of the function input (s) and the output.

To define the function input and output types you use the function name followed by two colons, then the types of its inputs and outputs, separated by `->` arrows.

Here is an example using the `cylinderArea` function defined later on:
```Haskell
cylinderArea :: Double -> Double -> Double
```

Notice that we do not explicitly define which are input types and which are output types. But, remember that a function in functional programming can only have one output meaning, all types but the last refer to inputs, in their corresponding order.

>[!Warning] Do not use `()` to aid readability because the Haskell compiler will think you mean a list or tuple of `Doubles` rather than two individual `Double` inputs.


#### Where and Let Keywords
When defining a function, you might end up having a messy load of duplicated or long expressions. This is where the `where` and `let` keywords come in! They allow you to define local variables to simplify the understanding of a function body.

**Where**
You define the function body with your chosen variable names, then use the `where` keyword followed by the definitions for the variable names you have used.

Here is an example:
```Haskell
cylinderArea :: Double -> Double -> Double
cylinderArea r h
 = sideArea + (2 * topArea)
   where
   sideArea = 2 * pi * r * h
   topArea  = pi * r * r
```

**Let**
Now, `let` is extremely similar to `where`, but you define the variables before the function body.

Here is an example using the same `cylinderArea` function from above:
```Haskell
cylinderArea :: Double -> Double -> Double
cylinderArea r h
 = let
   sideArea = 2 * pi * r * h
   topArea  = pi * r * r
   in
   sideArea + (2 * topArea)
```

Notice, you must use `in` in conjunction with `let`.

The difference between them is very much similar to the difference between `while` and `do-while` loops! Simply the order of definition.
