
#### Parallelism in Functional Programming
In regular programming, the problem with parallelism, implemented using threads, is that you cannot easily control what threads do and in what order without adding explicit safe guards, which can lead to loos of data integrity.

Fortunately, because there is not concept of state and nothing is stored in functional programming, these problems simply don't exist for functional programs.

Therefore, ANY part of a functional program can be parallelised.

#### An Embarrassment of Parallelism
Since any and all parts of a functional program can be parallelised, they are cursed with embarrassment of parallelism, where there are so many tasks, threads, that the multi-core processor is overwhelmed, saturated, to the point there each core has a substantial queue of tasks, threads, which are then executed sequentially.

Therefore, just because an expression could be evaluated in parallel, doesn't mean it should be.
