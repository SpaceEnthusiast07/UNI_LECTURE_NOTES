
#### Fundamental Concepts of Security
**Confidentiality** - Protecting data from unauthorised access
**Integrity** - Protecting data from unauthorised modification
**Availability** - Ensuring data is available to authorised people

*Authorisation* is the corner stone of security!


#### Identity and AAA
I think of a **subject** as a *person* and an **object** as a *file*, *system*, or *resource*.

**Identification** - Associating an identity with a subject
**Authentication** - Verifying a subjects identification
**Authorisation** - Granting or denying a subject access to an object
**Access Control** - Controlling the level of access subjects have to different objects


#### Methods of Authentication
Something that you *know* - e.g. password or PIN
Something that you *have* - e.g. a smart card or one-time password generator
Something that you *are* - e.g. biometrics

Your *current location* can also be incorporated into the authentication process.

**Passwords** - strong passwords are long and random and systems should let you input a password of any length with any character
**Hardware Tokens** - physical ID cards
**Biometrics** - your fingerprint, face, or retina


#### Access Control
Access control focuses on authorisation - controlling who has access to what
Access control comes in many forms:
 - Physical control - gates and turnstiles
 - Network traffic - firewalls
 - Hardware - memory management
 - Operating Systems - file system
 - Application level - google login


#### Policies vs. Models
A **security policy** defines what is allowed and forbidden
A **security model** is a formal representation of a class of systems


#### The Access Control Matrix Model
Sounds scary, but it is simply a table (matrix) where columns represent files/resources and rows represent subjects/users. The cells represent the access rights the given user has for the given file/resource.

#### Role-Based Access Control (RBAC)
Core Ideas:
 - Create **roles** that *reflect job responsibilities* within an organisation, e.g. staff and students in schools. 
 - Assign users to different roles, based on their job responsibilities.
 - Assign **permissions** to different roles.

RBAC decouples permissions and users by introducing roles.

This is a simple example of one implementation of RBAC, but there are many other ways of implementing this same idea.

RBAC is formalised using:
 - a set of ROLES
 - a set of USERS
 - a set of PERMISSIONS
 - a relation UA $\subset$ USERS $\text{x}$ ROLES
 - a relation PA $\subset$ ROLES $\text{x}$ PERMISSIONS
